\section{Назначение журнала}

Этот документ нужен не как дублирование CSV-артефактов, а как человеческий журнал исследования.
Машинно-читаемые результаты остаются в \path{data/results/*.csv}, а здесь фиксируются:
\begin{enumerate}[label=\arabic*.]
  \item существенные изменения алгоритмов;
  \item параметры и протокол конкретных прогонов;
  \item выводы по результатам сравнения;
  \item решения о том, что считать baseline и куда двигаться дальше.
\end{enumerate}

\section{Как вести журнал}

В проекте удобно разделить журнал на два слоя:
\begin{enumerate}[label=\arabic*.]
  \item \textbf{Ручной слой.} После каждого содержательного изменения алгоритма или экспериментального протокола в файл \path{docs/experiment_journal/journal_entries.tex} добавляется одна запись с кратким описанием изменения, указанием артефактов и выводом.
  \item \textbf{Автоматический слой.} Таблицы со сводными результатами не переписываются руками, а генерируются из текущих CSV через скрипт \path{experiments/build_latex_journal.py}. Его результат сохраняется в \path{docs/experiment_journal/generated_tables.tex}.
\end{enumerate}

Такой формат особенно удобен для курсовой: журнал остается читаемым, но при этом не расходится с фактическими численными результатами.

\section{Текущая исследовательская гипотеза}

Рабочая гипотеза проекта состоит в том, что для задачи множественного коммивояжера в условиях фиксированного временного бюджета до 60 секунд более сильные эвристики, сочетающие построение начального решения и последующее локальное улучшение, должны давать лучшее значение целевой функции \texttt{MINSUM}, чем простые baseline-стратегии.

Для текущей линии исследования это означает следующее:
\begin{enumerate}[label=\arabic*.]
  \item baseline-методы \texttt{rand+nn} и \texttt{2opt+greed} используются как нижняя планка;
  \item \texttt{grasp} и актуальная версия \texttt{lkh-wrapper-v2} используются как более сильные методы;
  \item прогресс новой версии алгоритма оценивается в том числе по уменьшению gap относительно канонического reference baseline от OR-Tools.
\end{enumerate}

\section{Протокол воспроизводимости}

Чтобы журнал действительно был исследовательским инструментом, а не просто текстовым приложением, в каждой существенной записи желательно фиксировать:
\begin{enumerate}[label=\arabic*.]
  \item используемый набор инстансов и его параметры;
  \item алгоритм и его параметры запуска;
  \item источник reference baseline;
  \item путь к CSV-артефактам;
  \item короткий вывод о том, улучшилось ли качество решения, время или устойчивость.
\end{enumerate}

На текущем этапе каноническими численными источниками для mTSP являются:
\begin{itemize}
  \item \path{data/results/mtsp_results.csv};
  \item \path{data/results/mtsp_summary.csv};
  \item \path{data/results/mtsp_reference_results.csv};
  \item \path{data/results/mtsp_reference_summary.csv};
  \item \path{data/results/lkh_versions_reference_summary.csv}.
\end{itemize}

\section{Следующие шаги}

Следующий цикл улучшений удобно вести по одной версии за раз:
\begin{enumerate}[label=\arabic*.]
  \item выделить новую версию \texttt{lkh-wrapper-v3} в отдельный файл;
  \item зафиксировать, какое именно изменение вносится относительно \texttt{v2};
  \item прогнать ту же сетку тестов и сравнить результат с каноническим reference CSV;
  \item добавить одну короткую запись в журнал с выводом, стало ли лучше по \texttt{gap}, времени и устойчивости.
\end{enumerate}
